# Remediate Symfony HttpFoundation CVE-2026-108082

## Destination

Remove the starter's locked exposure to CVE-2026-108082 by adopting the latest compatible stable
`symfony/http-foundation` release available at implementation time, including the upstream regression correction.
Prevent dependency resolution below 8.1.9 while preserving existing application behavior and verification strength.
This is a bounded dependency-security destination, not a general dependency refresh or deployment claim.

## Decisions so far

John approved narrow remediation rather than an ongoing dependency-security build gate, requested the latest
possible upgrade, and confirmed the summarized scope below. Approval permits requirement planning, not dependency
changes or implementation without separately approved, authorized TASKs under [local conventions](../CONVENTIONS.md).

At planning time, `composer.lock` selects HttpFoundation 8.1.6. The
[Symfony advisory](https://symfony.com/cve-2026-108082) identifies unauthenticated ReDoS in `HeaderUtils::split()`
through the Cache-Control request header. The vulnerability is fixed in 8.1.7, but releases 8.1.7 and 8.1.8
introduced a whitespace-separator regression corrected in 8.1.9. The
[Packagist release feed](https://repo.packagist.org/p2/symfony/http-foundation.json) listed 8.1.9 as latest stable
when inspected for this interview. Recheck available releases and compatibility during implementation rather than
assuming that version remains latest.

[TASK-00003](../tasks/00003-TASK.md) addressed PHP-runtime security, not this dependency remediation. Its completion
does not establish that this Symfony advisory is resolved. This EPIC is independent of the broader engineering
alignment EPIC and AccessControl application investigation.

## Scope and exclusions

- Upgrade HttpFoundation to the latest stable release compatible with the existing PHP/Symfony application baseline;
  change other dependency selections only where necessary for that upgrade and explain each such change.
- Express a durable dependency-resolution floor of 8.1.9, not merely a patched lock selection. Do not suppress or
  ignore the advisory to obtain a passing audit.
- Preserve public Fight package contracts, Symfony composition, the HTML homepage, explicit web JSON middleware,
  and bare-Kernel console behavior. Consume package fixes through Composer, never copied or edited vendor source.
- Verify the target advisory's clearance and the security fix's regression correction through appropriate safe,
  bounded checks. Retain exact Unit-only owned-production coverage and meaningful integration/HTTP journeys.
- Exclude unrelated package upgrades, framework-major migrations, new application features, runtime/topology changes,
  ongoing security-audit gate automation, and a broader security audit. Any necessary change beyond this boundary
  returns to John for a scope decision rather than silently expanding the upgrade.
- No publication, merge, release, production remediation, deployment, or claim of globally clean security is granted.

## Completion criteria

- The resolved and installed HttpFoundation version is the latest compatible stable release identified at
  implementation time, at least 8.1.9, with compatibility and necessary dependency changes evidenced.
- Composer constraints prevent resolution below 8.1.9. Fresh locked dependency audit evidence no longer reports
  CVE-2026-108082 / PKSA-xmwy-rmx5-m7h4; any other findings are disclosed separately rather than hidden.
- Safe verification demonstrates preserved relevant header-parsing behavior, including whitespace separators,
  and retained HTML, explicit web JSON, and bare-Kernel console behavior.
- The canonical `./bin/build` passes without weakening checks, coverage requirements, or retained journeys.
  Independent review and applicable QA evaluate the eventual TASK implementation under existing local rules.
