# Fight Common 1.2 Adoption and Lean Quality Gate

## Problem Statement

The starter needs a lean, Symfony-owned pre-submit gate while consuming Fight Common as a released Composer package.

## Solution

Adopt released Fight Common 1.2 with its optional PHPCS standard and use one Docker-backed `./bin/build` to verify
owned production code and retained Symfony behavior. Keep the future 2.0 migration visible but non-executable.

## Implementation Decisions

- The normal lockfile records the installed release; no candidate, lowest-lock, or receipt evidence is needed.
- The starter owns its framework-native configuration; Fight Common remains a Composer dependency only.
- Public HTTP composition is explicit at the front controller, while console and production checks boot the bare
  adapter-owned Kernel; configured providers are grouped by capability and do not imply event storage.
- Direct Unit tests own exact statement coverage; framework-boundary and journey suites use `#[CoversNothing]`.
- 2.0 may not define speculative breaking changes before Fight Common publishes its owning migration authority.

## Testing Decisions

- Run `./bin/planning-check` and the one Docker-backed `./bin/build` before committing. The build runs syntax,
  installed-standard PHPCS, PHPStan, Deptrac, Rector, exact Unit coverage, Integration, and Functional journeys.

## Out of Scope

- Copied Fight Common source, a nested starter application, central cross-repository builds, releases, and publication.
