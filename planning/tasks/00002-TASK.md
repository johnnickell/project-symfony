# Codify Symfony Engineering and Independent Review Guidance

## Outcome

Deliver one consistent local engineering and independent-review contract for contributors and reviewers under
[T-00009](../tickets/00009-TICKET.md) and [EPIC-00001](../epics/00001-EPIC.md). One documentation PR keeps contributor
rules and reviewer expectations aligned rather than introducing a partial contract. Follow
[CONVENTIONS.md](../CONVENTIONS.md); this TASK does not redesign the active planning lifecycle.

John approved this single-TASK scope in the decomposition conversation. `ready-for-human` means execution
approval and checkout/worktree selection are next, not that implementation or independent review has occurred.

## Scope

- Codify inward ownership, direct public-package composition, the justified owned-orchestration test, PHP/naming/
  docblock rules, framework exceptions, and Action/Responder responsibilities in focused local guidance.
- Define meaningful behavior-test selection, regression-first repair, direct tooling diagnostics, and preservation
  of exact Unit-only coverage and retained integration/HTTP journeys.
- Define independent Spec and Standards review, snapshot identity, criterion-to-evidence mapping, findings,
  limitations, and implementation/review handoffs with distinct verification and delivery states.
- Synchronize [AGENTS.md](../../AGENTS.md), [CONTRIBUTING.md](../../CONTRIBUTING.md), focused guidance under
  `planning/agents/`, and [TASK handoff references](../tasks/_TASK_TEMPLATE.md). Inspect linked callers, including
  onboarding and planning guidance, and reconcile contradictory instructions within this documentation boundary.
- Identify precisely which current instructions are superseded; link shared lifecycle authority instead of
  duplicating it. Preserve legacy completion evidence and historical records.
- Keep installed public package contracts and the current build/test mechanics unchanged. Describe existing
  operational requirements, not the future gate implementation assigned to [T-00010](../tickets/00010-TICKET.md).

Out of scope: production code/refactoring, dependency or vendor changes, gate/tooling implementation, new HTTP or
security behavior, deferred API decisions, global standards rollout, documentation/tooling product tests, new
lifecycle machinery, publication, merge, release, deployment, or archive operations. Existing presentation and
behavioral-test alignment remain with T-00011 and T-00012 respectively.

- [ ] AC-01 — Engineering guidance makes inward dependency direction, direct public-package composition, no
      renaming/forwarding wrappers, and the owned-orchestration test actionable without speculative layers or
      service location. Maps to T-00009 AC-01.
- [ ] AC-02 — PHP, naming, and docblock guidance states strict types, constructor injection, guard clauses,
      final/readonly expectations and justified framework exceptions, preserving the installed standard and
      immutable upstream names/contracts. Maps to T-00009 AC-02.
- [ ] AC-03 — HTTP guidance separates transport translation, presentation, and authoritative policy; covers
      safe Views and explicit wire mapping; preserves the pure-presentation HTML homepage and middleware/bare-Kernel
      boundaries; and routes exact API/security decisions to their existing owners. Maps to T-00009 AC-03.
- [ ] AC-04 — Testing guidance preserves meaningful owned behavior and package integration evidence, regression-first
      repair where feasible, direct tooling diagnostics, exact 100% Unit-only owned-production statement coverage,
      and retained journeys. It documents denominator/exclusions, driver, warnings, and gaps without widening
      exclusions, weakening assertions, or using combined-suite coverage as a substitute. Maps to T-00009 AC-04.
- [ ] AC-05 — Review guidance defines independent Spec and Standards passes, exact branch/base/head and relevant
      working-tree identity, criterion-to-evidence mapping, findings/disposition, warnings, unverified areas,
      remaining risks, and next authorized action. One independent reviewer may perform both passes; a material
      contributor cannot accept the TASK. Maps to T-00009 AC-05.
- [ ] AC-06 — TASK handoff references carry actual implementation, verification, and independent review evidence.
      They distinguish implementation completion, requirement progress, local/hosted results, acceptance,
      publication, merge, release, and deployment. Missing required proof prevents acceptance; a green build alone
      is not semantic review. Maps to T-00009 AC-06.
- [ ] AC-07 — Agent instructions, contributor onboarding, focused guidance, and handoff callers agree, link shared
      authority, and identify precise supersession without rewriting history. Exceptions name rationale, owner,
      affected requirement, acceptance, and verification path without private dependencies. Maps to T-00009 AC-07.
- [ ] AC-08 — Recorded ordinary-feature and revision/missing-evidence walkthroughs, caller inspection, fresh
      canonical verification, and independent Spec and Standards review establish the delivered guidance. No
      production behavior, gate implementation, or PHPUnit tests of documents/tooling are introduced. Maps to
      T-00009 AC-08.
