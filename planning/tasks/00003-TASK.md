# Require Patched PHP Runtimes

## Outcome

Require patched PHP 8.5 runtimes for the existing FPM application and CLI build, closing the repository's
stale-runtime exposure to CVE-2026-109618 and CVE-2026-109619. This is a standalone bug under
[planning conventions](../CONVENTIONS.md), not a new runtime topology or dependency-upgrade project.

John approved this bounded scope and TASK creation after diagnosis, and selected an isolated worktree.
John subsequently invoked Build for this checkout, authorizing the bounded delivery sequence; scope approval
and execution authority do not assert verification or independent acceptance.
Priority is urgent before serving web requests; no ordering relative to unrelated TASKs is imposed.

## Scope

- In scope: `etc/docker/fpm/Dockerfile`, `etc/docker/build/Dockerfile`, affected PHP configuration,
  Composer PHP minimum/platform and corresponding lock metadata, and directly affected rebuild guidance.
- Select verified patched images within PHP 8.5, at least 8.5.12; keep FPM and build compatible. Follow the
  applicable PHP image-selection direction in [WF-002](../wayfinder/tickets/WF-002-local-development-runtime-contract.md)
  without implementing its broader topology.
- Ensure the owned preparation path selects patched images rather than silently retaining vulnerable cached
  bases. Document explicit rebuild/container recreation and prove the actual CLI and FPM versions.
- Set `session.upload_progress.enabled=0` before request parsing, following PHP's October 23 precaution.
- Align Composer's PHP minimum and simulated platform without unrelated package upgrades.
- Out of scope: other roundup advisories, Nginx upgrades, application features, new services, full WF-002
  isolation/topology implementation, package-owned source, production deployment, incident response,
  credential rotation, publication, release, or visibility changes.

## Reproduction and diagnosis limits

The [PHP October 21 security advisory and October 23 upload-progress notice](https://www.php.net/archive/2026.php)
identify PHP 8.5.12 as fixing the two reported critical runtime CVEs. The later notice recommends disabling
upload progress pending a further fix; it does not mean 8.5.12 resolves every possible session-related issue.

At the diagnosis checkout revision `e510e90e546dd5f03a2c252cc1c8b3985c9bcb12`, image metadata reported
`project-symfony-api:latest` as PHP 8.5.7 and `project-symfony-build:latest` as PHP 8.5.10. The Dockerfiles
select floating PHP 8.5 tags, and `bin/up` and `bin/build` do not explicitly refresh base images.
Expected: PHP 8.5.12 or newer within the selected line. Observed: cached image metadata below that floor.
Composer's simulated 8.5.4 platform is not an actual runtime measurement.

No container was running for the diagnosed checkout. Image metadata establishes a stale local baseline,
not an executed exploit, current production exposure, or compromise. Work must recheck its selected base and
capture an isolated failing version diagnostic before repair; do not start or probe a public vulnerable server.
If the stale images are no longer available, record that reproduction gap rather than inventing a failure.

## Validation and permissions

The threat is an unauthenticated request reaching a vulnerable PHP web runtime, risking process authority and
readable application secrets. No exploit execution or production access is needed or authorized. Composer package
updates alone cannot repair the PHP engine. A cached image tag or simulated platform alone is not proof of a fix.

Use isolated, non-networked, read-only version diagnostics without application/credential mounts where feasible.
Verify effective FPM configuration, not only CLI defaults. Never expose an unpatched diagnostic HTTP service.
Identify mounts, project names, image tags and ports before starting task-owned resources; do not replace or stop
another checkout's services. The current canonical build uses a shared image tag, so coordinate its use rather
than assuming the Git worktree isolates Docker resources. Preserve all existing checks and coverage requirements.
